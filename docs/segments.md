# 消息段对照

两侧的组件模型不同：Flandora 按 OneBot v11 的「段」收发，麦麦按自己的组件模型存消息。下面两张表是两侧的对应关系，改任一侧时两张表与 `tests/` 一起同步。

## 入站（微信 → 麦麦）

| OneBot 段 | 处理方式 |
| --- | --- |
| `text` | 原文传入 |
| `at` | 转成麦麦的 `at` 段，并据此置位「是否 @ 了机器人」 |
| `image` / `emoji` | 解码或读盘后作为图片传入，同时计算哈希；描述留空，由麦麦识图生成 |
| `face` | 转成文本 `[表情 id]` |
| `record` | 转成麦麦的语音段；描述留空 |
| `file` | 未超上限时以文件段传入（含文件名与内容） |
| `reply` | 以引用段传入，携带被引消息的 `message_id`；被引的是机器人自己发的消息时（事件上的 `reply_to_self`）按被 @ 处理，正文不改写 |
| `video`、合并转发、其它 | 转成占位文本，其余段照常送达 |

「被提及」有三个来源：段里指向自己的 `at`、事件上的 `is_mentioned`、事件上的 `reply_to_self`。三者都写进 `additional_config` 供宿主判断；`reply_to_self` 始终是事件里的真实值。

## 出站（麦麦 → 微信）

| 麦麦段 | 处理方式 |
| --- | --- |
| `text` | 原文发送（微信侧逐字投递并回读校验） |
| `at` | 数字 ID 发真 @；其它形态记入失败详情 |
| `image` / `emoji` | 内联字节直接发送；本机路径按文件名到 Flandora 的附件目录里取件 |
| `voice` | 以语音文件发送 |
| `file` | 内联字节或本机路径直接发送 |
| `合并转发` | 展开为 `[合并转发]` 段落文本后发送 |

出站目标（群或私聊）取自宿主下发的目标信息，必须是 Flandora 分配过的整数 ID；目标号缺失时这条消息直接失败，错误信息里给出原因。
